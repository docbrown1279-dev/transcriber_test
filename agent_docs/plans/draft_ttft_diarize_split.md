# Черновик: TTFT / диаризация (после шипа 15 мин)

**Статус:** IDEA — не в коде (спека направления A). Демка: `audio.max_minutes=15`, главы только после полного прогона.  
**Поле (VPS 2026-09-10):** 15′ → полный прогон **~10:37** wall (2 vCPU). Цель TTFT **~5–6 мин** через направление A; «пара минут» — только через B + Jina D.  
**Оркестрация A/B экспериментов:** [`ticket_d5_ttft_experiments.md`](ticket_d5_ttft_experiments.md).  
**Связано:** [`ticket_d5_diarize_speed.md`](ticket_d5_diarize_speed.md) (H0 warmup, окна, Jina note).

## Зафиксированные ограничения

1. **Packing C и спикеры.** Эмбеддинги глав/packing C опираются на speaker turns. Нельзя просто «ASR без диаризации» без смены каркаса TOC (вариант D / VAD-окна).
2. **WeSpeaker качество.** На демо-записи мужские голоса склеиваются; «лишние» id часто короткие крошки (~5 с). См. также [`ticket_d1_speaker_clusters.md`](ticket_d1_speaker_clusters.md). Смена эмбеддера (TitaNet/ERes2Net) в 1f2 **не** ускоряла и на клипах давала тот же счётчик — для TTFT не приоритет; для склейки мужчин — отдельный bakeoff порога/движка.
3. **Live TOC mode B.** Закрытие главы без absorb + публикация в UI = дыры (пример: C01 до 01:04, C02 с 03:08 при финальном C01 до ~03:06). Пока только финальный dump.
4. **Cold start.** Модели грузятся лениво при первом job — в TTFT первого пользователя после рестарта входит load; warmup — H0 в ticket_d5_diarize_speed.

## Направление A — разрезание файла (предпочтительно для TTFT при каркасе C)

**Цель:** первая usable глава **≤ ~5–6 мин** на 2 vCPU / клип 15′ (полный прогон сегодня ~10–11 мин).

### Идея

1. VAD на всём файле (дёшево).
2. Разрез по самой длинной паузе в окне ~40–60% длительности (fallback: mid-point).
3. **Part 1:** WeSpeaker только на первой половине → `turns_part1` → ASR → packing/titles → **ранний UI**.
4. **Part 2:** эмбеддинги хвоста; **кластеризация с якорем** на центроиды/дерево из part 1 (не независимый Agglomerative с нуля) → merge turns → ASR хвоста → дописать главы.
5. Финальный TOC: границы с absorb; спикер-id согласованы с part 1.

### Почему якорь обязателен

Два независимых кластера на половинах → один человек = два id. Пользователь это уже сформулировал: первичная кластеризация на первой части, финал дотягивает хвост к готовым кластерам.

### Риски

- Паузы посередине нет.
- Новый спикер только во второй половине (нужен порог «новый centroid»).
- Part 1 без absorb всё ещё может дробить главы — для раннего UI ок, на EOS полный remap.

### Метрики при прототипе

| Метрика | Gate (черновик) |
|---|---|
| TTFT (первая titled-глава) | ≤ 300–360 с на 15′ @ 2 CPU (warm) |
| Крупные спикеры (speech > 30 с) | стабильны part1→full (не разъезд id) |
| Глаз: мужские голоса | не хуже baseline полного WeSpeaker |

## Направление B — ASR-first + Jina D (отложено; «пара минут»)

VAD→ASR без спикеров → TOC как **вариант D** (`jina-embeddings-v3-hf` ~570M) → diarize в фоне → ретро-метки спикеров.

- Research 2b: C и D оба рабочие; победителя нет. Demo сейчас = **C + rubert-tiny2**.
- Jina **тяжёлая** относительно tiny2 (веса/RAM/CPU); на 8 ГБ рядом с GigaAM — отдельный риск.
- Ломает текущий контракт packing C; отдельный этап + образ/deps.

Только если A не бьёт 5–6 мин или продукт сознательно уходит на D.

## WeSpeaker follow-up (качество, не TTFT)
