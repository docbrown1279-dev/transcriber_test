# Тикет: D2 — минимальная длительность главы (и главы из одной фразы)

**Статус:** OPEN (backlog)  
**Ветка:** от свежего `main` → отдельная ветка chunking (не `cursor/demo-d4-web`)  
**Приоритет:** не блокирует веб-демку D4. Подхватить после merge UI, на слое packing C.

---

## Контекст

На демо-записи (~30 мин, job `3294b35f…` / повтор `db7a763f…`) в оглавлении есть крошки:

| id | duration_sec | source_ids |
|---|---|---|
| C02 | 10.85 | 1 |
| C04 | 5.80 | 1 |
| C06 | 25.63 | 4 |
| C07 | 10.54 | 5 |

`metrics.short_chapters = 4` при `target_chapter_sec: [45, 180]`. G2.3 это только **WARN**, пайплайн не склеивает.

Пользователь: глав ~10 с и глав из **одной фразы** быть не должно.

Сейчас в `config/base.yaml`:

- `absorb_shorter_than_sec: 5.0` — в `packing_c.absorb_short_units` склеиваются только единицы **строго короче 5 с**. 5.8 с и 10 с проходят пол.
- `target_chapter_sec: [45, 180]` — цель/метрика, **не** жёсткий пол при merge.
- Склейка соседей — по cosine (`similarity_threshold: 0.70`) и `merge_max_duration_sec: 180`. Низкая похожесть оставляет короткий остров.

Тест `tests/unit/test_packing_c.py` (`D2-ABS-01/02`) покрывает только порог 5 с.

---

## Цель

После packing C не оставлять «обрывков» в оглавлении:

1. Глава короче согласованного пола (предложение: **≥ 20–30 с**, уточнить на клипе; 45 с из G2.3 может быть слишком жёстко, если тема реально короткая).
2. Глава не состоит из **одной** непустой реплики (исключение — буквально последняя фраза встречи, если соседа нет).
3. G2.3 на том же 30-мин клипе: `short_chapters` ближе к 0 без раздувания соседних глав выше 180 с.

Не менять границы сегментов ASR. Только `source_ids` / start-end главы.

---

## Как реализовать (когда откроем)

Слой: `src/transcriber/chunking/packing_c.py` + `chunking.absorb_shorter_than_sec` (и/или новый `min_chapter_sec` / `min_chapter_segments`).

Порядок:

1. Снять с демо-job список short id + длительность + число реплик (без текста в логах).
2. Поднять absorb-пол **или** второй проход после `merge_similar_units`: пока глава `< min_sec` **или** `len(source_ids) < 2` — приклеить к предыдущей (первая крошка — к следующей), не превышая `merge_max_duration_sec` / верх `target_chapter_sec`.
3. Если оба соседа «толстые» — предпочесть того же спикера / выше similarity; не резать длинную главу ради баланса.
4. Юнит-тесты: 10 с / 1 сегмент после похожего блока → поглощён; 50 с одна реплика (если бывает) — отдельное решение, не ломать.
5. Прогон на 30-мин клипе; `voice_002` chapters **не** пересобирать, пока не попросит человек.

Не крутить `similarity_threshold` сеткой «на глаз». Сначала жёсткий пол по длительности/числу реплик.
