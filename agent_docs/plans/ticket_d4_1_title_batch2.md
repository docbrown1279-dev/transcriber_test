# Тикет: D4.1 — гибрид titles «первый сразу, потом батчи по 2»

**Статус:** OPEN (backlog)  
**Приоритет:** низкий для 30‑мин демо. Сейчас: mode **A** = один batch на все главы; mode **B** = 1 title при закрытии главы (появилась следующая).

---

## Идея

1. Как только закрылась **первая** глава → сразу один LLM-вызов (быстрый TTFT).
2. Дальше копить закрытые главы и слать **батчами по 2** (меньше round-trip, чем 1×N, но раньше полного конца ASR, чем полный batch A).
3. Хвост нечётный / EOS — добить оставшиеся 1–2.

## Зачем не сейчас

На демо 15–30 мин глав обычно ~8–20. Выигрыш «батч по 2» vs «1 на закрытие» небольшой против стоимости усложнения и риска частичных JSON. Полный batch A уже даёт 1 вызов на всю TOC после ASR.

Имеет смысл, если:
- включим streaming TOC в UI и API latency >> ASR slice, или
- глав станет много (час+), а TTFT важен.

## Когда открывать

После стабилизации B (title only on next-chapter) и решения по default A vs B в D5.
