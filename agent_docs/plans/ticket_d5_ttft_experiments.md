## Контекст поля

- VPS 2 vCPU: **15′ аудио → ~10:37** полный прогон (warm?). Цель TTFT (первая полезная глава): **~5–6 мин**.
- Демо-каркас: packing **C** + rubert-tiny2 → диаризация **до** TOC обязательна.
- Текущие окна embed в `config/base.yaml`:

```yaml
diarization.embed:
  window_sec: 1.5
  step_sec: 0.75
  cluster_distance_threshold: 0.85
```

Мельче **1–2 с** окна для совещаний почти бессмысленно: это не live-спорт, короткие реплики редки; перебивания и так плохо ловятся мелким шагом, а число окон (и wall) растёт почти линейно от `1/step_sec`.

## Сценарии эксперимента (порядок)

### S1 — грубее окна WeSpeaker (быстрый A/B)

**Гипотеза:** `window/step` ↑ → меньше embed-вызовов → diarize wall ↓; на совещаниях качество не хуже (или приемлемо).

Кандидаты (не мельче текущего смысла «≥1–2 с»):

| preset | window_sec | step_sec | грубо окон vs baseline |
|---|---|---|---|
| baseline | 1.5 | 0.75 | 1× |
| A | 2.0 | 1.0 | ~0.75× |
| B | 3.0 | 1.5 | ~0.5× |

**Метрики:** wall diarize; число speaker id; глаз на 2 файлах (инж. vs «картинки»/job выше); не ломать женщину в общий пул.

Детали замера embed vs cluster — H1/H2 в ticket_d5_diarize_speed.

### S2 — разрез файла + якорь (главный рычаг TTFT)

Как в [`draft_ttft_diarize_split.md`](draft_ttft_diarize_split.md):

1. VAD целиком → разрез по длинной паузе ~40–60% (fallback midpoint).
2. Diarize+ASR+TOC только **part1** → ранняя глава в UI.
3. Part2: embed хвоста, **кластер с якорем** к центроидам part1 (не два независимых Agglomerative).
4. Merge turns / финальный absorb TOC.

**Критично — гонки / каша:**

- Один writer артефактов на job; part2 не публикует конфликтующие `SPEAKER_*` без remap.
- UI: либо «главы part1 + хвост pending», либо ждать merge — **не** live partial без absorb (уже обожглись).
- Якорь спикеров обязателен, иначе один человек = два id после склейки половин.

Gate (черновик): TTFT ≤ 300–360 с на 15′ @ 2 CPU (warm).

### S3 — постфильтр крошечных кластеров (длинные записи)

Если суммарная речь кластера **≲ 2–3 с** → прилепить turns к **ближайшему** соседу по времени (или к ближайшему центроиду).

- Только для длинных записей (порог длительности файла, напр. >5–10 мин) — на коротких клипах крошка может быть единственной репликой человека.
- Не путать с `absorb_turn_shorter_than_sec` (короткий **turn**, не весь speaker id) — см. ticket_d1_speaker_clusters.
- После S1/S2: иначе оптимизируем шум поверх плохого порога.

### S4 — вне scope (явно)

- Jina / late chunking D / diarize в самый хвост пайплайна.
- Live TOC mode B с дырами.
- pyannote torch на 2 vCPU.
