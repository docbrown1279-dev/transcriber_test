## Замороженный ASR (без изменений)

На **полном** `data/fixtures/meeting_sample.m4a` (~24.5 мин), не на eval-клипах:

1. **pyannote** `speaker-diarization-3.1` на исходном файле (не loudnorm, не Silero, не ffmpeg silence).
2. Merge **в таблице**: тот же спикер, gap ≤ 0.3 с → `[min, max]`; turn &lt; 1 с всосать в соседа. Дыры ≥ 0.5 с не извлекать.
3. Extract `ffmpeg -ss START -to END` из оригинала. **Linear `volume=`** только если RMS &lt; −30 dBFS (к −23, cap +18 dB, peak ≤ −1 dBFS). Без denoise, без `loudnorm` / компрессора.
4. **GigaAM `v3_rnnt`** (как на 1e). Turn &gt; 25 с резать только по времени — лимит модели, не фолбэк. Пустой текст оставлять пустым. **Никакого** Whisper / Podlodka / второй ASR.

Выход: `results/asr/2/gigaam_v3_rnnt/` (json+txt, спикеры, clip-time = время полного файла). Если такой прогон уже есть и стек тот же — не пересчитывать.

## Чанкинг (эмбеддинги)

Урок 1a: `multilingual-e5-small` по **коротким** ASR-сегментам при пороге 0.7 склеил **всё в 1 чанк**; 0.8 дал 13 рваных границ. Сначала пакуем реплики, потом сравниваем **соседей**.

Единица размера — **слово** (lower, ё→е, без пунктуации), не BPE.

**Модель эмбеддингов (1 шт.):** `cointegrated/rubert-tiny2`. Если не встаёт за ≤2 pip — стоп, `failure_kind: install`. Не e5-small, не 600M.

Алгоритм (только **соседи по времени**, не кластеризация по всей встрече):

1. Единица = одна или несколько **целых реплик одного спикера**, суммарно ориентир **20–50 слов**. **Не резать реплику посередине.** Резать внутри реплики только если она сама аномально длинная (больше ~80 слов) — на границе предложения / ASR-сегмента внутри неё.
2. Чанк₀ = первая единица.
3. Следующая единица: косинус к текущему чанку. Старт: **≥ 0.80** → дописать. Иначе — новый чанк.
4. Новый чанк, если пауза между единицами **&gt; 90 с**.
5. В эмбеддинг — только текст, без id спикера. В JSON чанка спикеры и времена остаются.

Целевое число чанков на эту запись (~20–25 мин): **5–30**.

**До 3 попыток** — только размер единицы (слова) и порог косинуса. Попытка 1: 20–50 слов, порог 0.80. Если счётчик вне 5–30: ещё 1–2 прохода (например меньше окно / выше порог, если слиплось в 1 чанк; больше окно / ниже порог, если слишком много обрывков). Не менять эмбеддер, не резать реплики иначе, не добавлять ASR.

После **третьей** попытки, если всё ещё не 5–30 — **стоп**. Qwen не запускать. Записать все три `(unit_size, threshold, num_chunks, cosine stats)` в notes. Дальше думаем иначе, не четвёртая схема в том же прогоне.

Qwen-заголовки — если **какая-то** из попыток попала в 5–30: взять её (при нескольких — ближайшую к середине диапазона, ~12–15).

## Таймназвания

Если число чанков в **5–30**:

- Локально **Qwen3-8B** (GGUF Q5_K_M, иначе Q4). Только текст чанка, **без аудио**, без API.
- На чанк: заголовок **не больше 10 слов**, русский, по содержанию. Не выдумывать ответственных, решения, цифры, которых нет в тексте (урок 1a).
- Не саммари встречи и не саммари чанка — только короткое имя для таймкода.

## Логи и артефакты

- Полный текст ASR (json+txt).
- Каждая попытка чанкинга (≤3): размер единицы, порог, `num_chunks`, `embed_runtime_sec`, `{start, end, n_words, text}`.
- Финал: `{start, end, title, text, speakers}`.
- `llm_runtime_sec` суммарно и по чанкам.
- Отчёт: `results/reports/2/` (`research_report.json` + `notes.md` по-русски).
