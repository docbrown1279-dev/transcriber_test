# Наблюдения Stage 1

## Возобновление и ограничения

- На старте в репозитории были только пустые шаблоны отчётов; завершённых экспериментов и вызовов API не было.
- Выполнен только Stage 1. Тестовый фреймворк Stage 2 не создавался.
- Исходный файл: `data/fixtures/meeting_sample.m4a`, длительность 1468,6 с (24,5 мин), размер 23,99 МБ.
- Лимиты соблюдены: 1 попытка `faster-whisper`, 1 метод denoise с одним A/B, 1 модель эмбеддингов с исходным порогом и одним разрешённым сдвигом, 1 локальная LLM, 1 вызов Gemini, 0 вызовов NVIDIA.

## Среда

- Linux x86_64, 4 логических CPU, 15 GiB RAM, без swap и без GPU.
- На старте было 234 GiB свободного места.
- Python 3.12.3, ffmpeg 6.1.1, GCC 13.2, CMake доступны.
- Эффективная политика сети проверена для текущего pod через сведения Cursor Cloud: `Allow all` (`restricted: false`).
- Переменная HF-токена отсутствовала. Публичная модель не требует аутентификации, поэтому это не считалось блокером.
- Переменные Gemini и NVIDIA присутствовали; значения не читались и не выводились.

## Сетевой preflight

- Анонимный preflight выполнен до ASR.
- Запрос публичных весов `Systran/faster-whisper-medium` с последованием редиректа завершился HTTP 200.
- DNS и TLS успешны; итоговый TLS verify result: 0.
- Точный хост редиректа для файла модели: `us.aws.cdn.hf.co`, путь Xet: `/xet-bridge-us/...`.
- Сравнение с токеном не выполнялось, так как анонимный доступ работал.
- Санитизированное доказательство: `results/asr/network_preflight.json`.

## Установки

Создана `.venv`. Установка каждого семейства была успешна с первой попытки:

- `faster-whisper==1.2.1`
- `pymorphy3==2.0.6`
- `pymorphy3-dicts-ru==2.4.417150.4580142`
- `sentence-transformers==6.0.0`
- `jsonschema==4.26.0`
- `llama-cpp-python==0.3.35`

Кэш Hugging Face использовал стандартный каталог `$HOME/.cache/huggingface`. Официальные GGUF-шарды `Qwen/Qwen2.5-7B-Instruct-GGUF` Q4_K_M сохранены локально под `models/qwen2.5-7b-instruct-q4_k_m/`; в git они не добавлялись.

## ASR

- `faster-whisper medium`, CPU, `int8`, 4 потока, `beam_size=5`, VAD включён.
- Время загрузки/распознавания: 201,165 с; это примерно в 7,3 раза быстрее длительности записи.
- Определённый язык: `ru`, вероятность 1,0.
- Получено 133 сегмента и 1188 кириллических слов.
- Метрика `pymorphy3.word_is_known`: 1144/1188 = 0,962963, порог 0,9 пройден.
- Проверены четыре фрагмента, распределённые по записи. Они сохраняют смысл, хотя есть локальные ошибки распознавания.
- В полном тексте встречаются отдельные посторонние символы и искажённые термины. Метрика по кириллическим токенам сама по себе этого не отражает, поэтому её нельзя трактовать как WER.
- `large-v3` не запускался: после прохождения medium порога качества такой повтор противоречил бы заданному порядку попыток.

Артефакты: `results/asr/faster_whisper_medium_attempt1.{json,txt}` и `results/asr/faster_whisper_medium_attempt1_metrics.json`.

## Denoise, отдельный A/B

Проверен один метод: `ffmpeg` с `highpass=f=80,afftdn=nf=-25`. Для исходного и обработанного файла использована одна и та же конфигурация ASR.

- До: коэффициент 0,962963, 1188 кириллических слов.
- После: коэффициент 0,972973, но только 518 кириллических слов и 36 сегментов.
- Выборочные фрагменты после фильтра осмысленны, однако большие интервалы речи исчезли. Небольшой рост словарного коэффициента маскирует сильное падение полноты.
- Вывод: эту настройку не использовать.

Обработанный WAV оставлен локально в `data/processed/meeting_sample_ffmpeg_afftdn.wav`; текстовые A/B-артефакты находятся в `results/denoise/`.

## Семантическое разбиение

- Модель: `intfloat/multilingual-e5-small`, локально на CPU.
- Вход: 133 соседних ASR-сегмента; нормализованные эмбеддинги и косинусное сходство.
- При плановом пороге 0,7 минимальное сходство было 0,762245, поэтому получился один чанк — явно сломанный результат.
- Выполнен единственный разрешённый сдвиг порога до 0,8: 13 чанков за 27,611 с.
- Некоторые границы соответствуют смене тем (сети связи, инженерные сети, квартирография), но другие отделяют короткую реплику или разрывают одну мысль.
- Вывод: фиксированный порог над короткими сегментами не прошёл выборочную проверку. Для следующего этапа разумно сначала объединять короткие реплики и затем калибровать границы, но в рамках Stage 1 это не реализовывалось.

Артефакты: `results/chunking/multilingual_e5_small.json` и `results/chunking/multilingual_e5_small_threshold_080.json`.

## Локальное саммари и API fallback

Локальная попытка:

- `Qwen2.5-7B-Instruct`, официальный GGUF Q4_K_M, `llama.cpp`, CPU, 4 потока.
- Входом был только локальный текст ASR.
- 2569 входных и 549 выходных токенов; 126,4 с, заметно ниже мягкого лимита 10 минут.
- Тематический обзор осмыслен, но модель без основания назначила «Разработчика» ответственным почти за все действия. Это считается галлюцинацией и провалом проверки извлечения действий.

Fallback API:

- Провайдер/модель: Google Gemini, `gemini-2.5-flash`.
- Причина: локальная модель нарушила запрет на выдумывание ответственных.
- Выполнен ровно один вызов, только с текстом стенограммы; аудио не передавалось.
- Время 5,071 с; 2187 входных токенов, 981 thinking token и 39 выходных токенов.
- Ответ оборвался после начала первого пункта и непригоден как саммари. Повтор не выполнялся.
- NVIDIA API не вызывался.

Артефакты: `results/llm/qwen2.5_7b_q4_k_m_summary.{md,json}` и `results/llm/gemini_2.5_flash_summary.{md,json}`.

## Итог

Локальный ASR пригоден как основа: `faster-whisper medium int8` дал читаемую стенограмму быстрее реального времени. Проверенный denoise ухудшил полноту, прямой E5-чанкинг коротких сегментов дал ненадёжные границы, а локальное саммари требует проверки фактов и ответственных. Полная связка для MVP пока не подтверждена, но ASR-компонент подтверждён.

## Stage 1b — обязательная проверка доступа HF

- Возобновление выполнено с сохранением всех артефактов Stage 1a. Результат `faster-whisper medium` рассматривается только как прежний baseline и не считается успехом Stage 1b.
- Проверка начата до установок, `loudnorm`, ASR и диаризации.
- Ни `HF_TOKEN`, ни `HUGGING_FACE_HUB_TOKEN` в среде не заданы. Значения секретов не читались и не выводились.
- Поэтому аутентифицированные GET-пробы `pyannote/speaker-diarization-3.1`, `pyannote/segmentation-3.0`, `pyannote/speaker-diarization-community-1` и публичного `Systran/faster-whisper-large-v3` не запускались: без токена такая проверка не подтверждает gated-доступ.
- Санитизированное доказательство записано в `results/asr/hf_access_preflight.json`: `token_present=false`, статус каждой пробы — `not_run`, `error_kind=missing_token`. Заголовки авторизации и токен в файл не записывались.
- По обязательному стоп-условию прогон завершён с `failure_kind=auth`. WhisperX/pyannote не устанавливались; fixture не преобразовывался и не передавался ни локальному ASR, ни API.
- `loudnorm`, WhisperX `large-v3`, отдельный faster-whisper + pyannote, whisper.cpp, Qwen3-8B meaning check и нейросетевой denoise не запускались.
- Chunking и summary пропущены как явно находящиеся вне скоупа Stage 1b. Вызовов Gemini/NVIDIA в Stage 1b не было, аудио в API не передавалось.

### Что требуется для продолжения

Задать `HF_TOKEN` или `HUGGING_FACE_HUB_TOKEN` и принять условия доступа ко всем трём репозиториям pyannote. Новый прогон должен снова начать с аутентифицированного HF preflight; только после HTTP-успеха всех gated-проб можно продолжать `loudnorm` и ASR с диаризацией.
